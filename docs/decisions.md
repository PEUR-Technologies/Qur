# Owner decisions after the handoff

These amend `docs/QUR_HANDOFF.md`. Newest last.

## 2026-10-23

1. **Unified top bar (like Zed).** Transparent macOS titlebar with full-size content. Only the traffic lights remain, inset into Qur's own top bar, which uses the window background with a 1 px hairline below. The bar holds the Qur symbol and the project switcher, drags the window, and zooms on double-click.
2. **Compact layout.** Sidebar 220 px with truncation ("…") instead of wrapping. Tight editor gutter and margins.
3. **Soft wrap** of editor lines at the editor width, on by default. Continuation rows have no line number.
4. **Terminal shortcuts.** The bottom panel holds several terminals in a slim tab strip (terminal tabs only; still no file tabs).
   - `Cmd+T`: new terminal (login `$SHELL`, cwd = always the project root, decision 39; Open Task Worktree in Terminal opens one in an agent's worktree).
   - `Cmd+Shift+T`: new terminal with `claude` already running (shell stays after it exits). Uses the CLI's own login; API keys are never set.
   - `Cmd+W`: close the focused terminal (kills its process group).
   - These override VS Code's `Cmd+T` (go to symbol) and `Cmd+Shift+T` (reopen closed editor). Neither exists in Qur v1 (no LSP, no tabs), so nothing is lost.
5. **Terminal pulled into the M0 spike.** The terminal panel (`alacritty_terminal`) is part of the M0 toolkit comparison, not deferred to M5.
6. **No Codex for now.** *(Reversed by decision 44.)* Codex is out of scope until the owner says otherwise. M0's acceptance becomes "Claude Code works on its subscription login". Do not ask for `codex login`. The roster and ACP client stay vendor-neutral, so Codex can be added back as config. M2's acceptance becomes three parallel Claude tasks.
7. **Full VS Code-style keymap + command palette.** Canonical list: `docs/keymap.md`. Every shortcut is also a palette command and, where macOS expects one, a native menu item. 
8. **Window transparency** (like the owner's Apple Terminal "Pro" profile). Config `[window] opacity` (0.5 to 1.0, default 1.0) and `blur` (default on when opacity < 1). Set from a small "Window: Transparency…" popover with a live slider (palette and View menu). This is an approved exception to "no settings UI beyond the pickers". Only backgrounds go translucent; text, cursors, selections, borders and the logo stay opaque. The contrast test checks themes at opacity 1.0 and at the 0.5 floor over both white and black desktops.
9. **Everything in the native menu bar, like Zed** (`docs/menus.md`). No toolbars, gear icons or settings screens in the window. Every command is in a menu and the palette. Unavailable items are disabled, never hidden.
10. **Peek-layout cycle moved to `Cmd+K Cmd+L`** (handoff section 8 said `Cmd+Shift+L`). `Cmd+Shift+L` stays Select All Matches, as in VS Code.
11. **Codex packages uninstalled** (`@openai/codex`, `@agentclientprotocol/codex-acp`). Only `@agentclientprotocol/claude-agent-acp@0.94.0` stays installed.
12. **`Cmd+Shift+T` creates a full Claude agent task**, not a plain terminal. Decision 4 is amended for this key.
    - Qur creates a worktree outside the repo on branch `qur/claude/term-<n>`, from the main checkout's HEAD (same lifecycle as `+` in handoff section 10).
    - It runs the interactive `claude` CLI in a PTY in that worktree; this is terminal mode, not ACP.
    - The task appears in the agents sidebar with an accent and status. The terminal is its Chat view and also shows as a tab in the bottom panel. Its edits drive the heatmap through the file watcher. Review, Merge and Discard work as for any task.
    - The title starts as "claude terminal <n>" and becomes the first line the user types. Closing the tab stops the process; the task and worktree remain until Merge or Discard.
    - If the project isn't a git repo, the key shows a one-line message ("Claude tasks need a git repo") and does nothing else.
    - `Cmd+T` stays a plain shell in the project, or in the selected agent's worktree.
13. **Theme per project**, so windows for different projects look different at a glance.
    - **Storage, nothing in the user's repo:** `~/Library/Application Support/Qur/projects/<repo-id>.toml`, with `theme = "Tokyo Night"` and optionally `opacity`. `<repo-id>` = the first 12 hex chars of the root commit, as for worktrees, so the setting follows the project across clones, moves and renames. A folder that isn't a git repo is keyed by a hash of its absolute path.
    - **Resolution order:** project theme, then global `config.toml` theme, then Auto. Agent task worktrees inherit their project's theme, so a peeked agent never looks like a different project.
    - **Setting it:** the theme picker (`Cmd+K Cmd+T`, Qur > Theme…) gets a scope toggle at the top: "This project" (default once a project is open) / "All projects". Qur > Theme also gets "Use Default Theme for This Project", which clears the override.
    - **Per window:** each window is one project, so two projects open side by side show two themes. Switching the project in the top-bar switcher swaps the theme instantly with no state loss (decision rules from handoff 12a still apply).
    - **Identity cue:** the project name in the top bar uses the theme's primary text color; nothing else is added. The logo stays black or white by background luminance (never tinted).
    - Opacity (decision 8) can also be set per project with the same scope toggle in the Transparency popover.
14. **Toolkit: GPUI** (Zed git rev pinned in the workspace; upgrade on purpose, at most once per milestone, re-running the budget). Evidence: `docs/spikes/toolkit.md`.
15. **Idle memory budget is measured as physical footprint** (Activity Monitor "Memory", `footprint <pid>`), with RSS reported alongside. Same targets: idle < 80 MB, 3 agents < 150 MB.
16. **Section 15 defaults accepted:** repo at `~/qur`; no file tabs (not even as an option for now); "by PEUR Technologies" only in About. The 6-accent palettes are chosen in M1 and shown to the owner with the M1 report.
17. **"New Claude Task" is now called "New Agent Terminal"** (`Cmd+Shift+T`) in menus, the command palette and the empty-editor hints. Behaviour is unchanged (decision 12).
18. **No permanent code editor area** (amends handoff sections 7–8). The window is for **files and agent sessions**. Code opens in a **modal** over the window, which keeps full editing, find and save. **Esc** closes it, stepping out one layer at a time: close find, then collapse multi-cursor, then close the modal. Unsaved edits stay in memory: the file shows a dirty dot in the tree, and Cmd+S saves, also from inside the modal. Quitting with unsaved edits still asks first.
19. **M2 window layout.**
    - **Left column (resizable, 280 px default):**
      - AGENTS: ACP tasks and Agent Terminals.
      - TERMINALS: plain shells, shown only when there are any.
      - FILES: expanded by default and taking all remaining height. This replaces the earlier "collapsed dropdown".
      - The tree shows the selected agent's worktree, or the main checkout when no agent is selected.
    - **Stage (rest of the window):** the selected session.
      - ACP agent: header (name, status, branch), To-do strip, Chat stream, permission bar, prompt bar.
      - Agent Terminal or shell: the terminal itself.
    - The bottom panel is gone (Cmd+J has nothing to toggle and is disabled). Shells live in the stage like agents.
20. **Automated agent tests use a tiny prompt** to save the owner's Claude usage. The M2 parallel check is three tasks with a one-line prompt.
21. **Take Orca's ideas where they fit** (owner, 2026-10-23: "take a ton of features from orca"). The inventory is in `docs/research/orca.md`: 125 features, each marked Adopt, Adopt adapted, or Conflicts. Orca is MIT (GPL-compatible), but it's TypeScript/Electron, so we take ideas, not code. Features that conflict with a constraint (browser, hosted-git integrations, cloud/SSH, telemetry, a terminal daemon that outlives the app, push) are **not** adopted unless the owner says so per item.
22. **Orca features adopted in M2:**
    - `.worktreeinclude`. A repo-root file the user writes (Qur only reads it) with one gitignore-style path per line. Matching files and folders from the main checkout, like `.env` and `node_modules`, are copied into each new worktree with APFS copy-on-write (`cp -c`): instant and no extra disk.
    - A per-project setup command: `[worktree] setup = "pnpm install"` in `projects/<id>.toml`. It runs in the new worktree through the login shell before the agent starts. Its output shows in the chat, and the agent starts only on success.
    - Sidebar rows show the agent's last message, and an unread marker on agents that finished or need you while not selected.
    - Composer: `/` opens the agent's slash commands (from ACP `available_commands_update`). Messages sent during a turn are queued and sent when it ends.
23. **Defaults accepted (2026-10-23):** the Qur Light/Dark accent palettes as proposed; Kotlin stays bundled; none of Orca's "conflicts" items are adopted.
24. **Pre-trust task worktrees for the Claude CLI** (Orca item, owner approved). When Qur creates a worktree for a terminal-mode Claude task, it marks that folder trusted in `~/.claude.json` (`projects["<worktree>"].hasTrustDialogAccepted = true`), so "Do you trust this folder?" doesn't stall the agent. Qur only adds or updates that one key, writes atomically, and never touches anything else in the file.
25. **Live view lives in the agent stage, as a split** (owner choice for M3). The handoff's peek layouts apply inside the stage:
    - **A Watch + side notes** (default): Live on the left; To-do, Chat and the prompt on the right.
    - **B One view at a time:** Live / To-do / Chat / Changes segments, `Cmd+1..4`.
    - **C Watch + drawer:** Live fills the stage; a bottom drawer shows the current step and latest chat line, and expands to the chat.

    Cycle with `Cmd+K Cmd+L` or View > Peek Layout; the choice is saved in `config.toml` (`peek_layout`). The code modal (decision 18) stays for opening any file yourself; Live is only the agent's current file.
26. **Embedded browser with Inspect** (owner, 2026-10-23). This overrides the handoff non-goal "embedded browser, design mode" and the no-webview rule, for this feature only.
    - **What:** a Browser view in the agent stage, next to Live, like VS Code's Simple Browser. Inspect highlights and selects elements, and "ask an agent to adjust" sends the selection's context to that task's agent.
    - **How:** the system WKWebView (no bundled engine). Pages run in WebKit's own processes. It's opt-in per task and freed when idle.
    - **Measured cost** on the owner's Mac (M3 probe): +8 MB in Qur's own process and about +55 MB in WebKit's processes for a simple page. Those processes exit when the page closes.
    - Modelled on Orca's Design Mode (`docs/research/orca.md`, item P8).
27. **Sidebar: agents are buttons, only FILES is a dropdown** (owner, 2026-10-23). Amends decision 19.
    - AGENTS: each ACP task and Agent Terminal is a button with its accent dot and title (plus `+n −m`, `⚠`, `!`, `✓`, `✕` or "stopped" on the right). It fills with the agent's accent while the agent is active (ACP: starting, working or needs you; terminal: output in the last 2 s). The selected agent gets an accent outline.
    - Clicking an agent's button opens its session: an Agent Terminal's terminal (restarted in its worktree if it had stopped), or an ACP agent's stage.
    - FILES is the only collapsible section: its header toggles the tree (chevron), open by default. TERMINALS and SOURCE CONTROL stay plain sections.
28. **Merge conflict and Git commands in the palette and menus** (decision 7 applied to M4). Agent > Merge Conflicts holds Next Conflict, Previous Conflict, Accept Ours, Accept Theirs, Accept Both, Finish Merge and Abort Merge; they are enabled only while a merge is stopped on conflicts. View > Git holds Stage All Changes, Unstage All Changes and Commit Staged… (which commits with the typed message, or focuses the message field when it's empty). The conflict bar and Git panel buttons stay as they were.
29. **Features from OpenADE and PandaCode** (owner, 2026-10-23: "check their work, implement the best features", with "remember the constraints, lightest ADE in the market"). The inventory is in `docs/research/openade-pandacode.md`; as with Orca, we take ideas, not code (OpenADE's licence is unclear and PandaCode's MIT carries a fork-attribution clause). Adopted so far:
    - **Turn-end checks.** `[checks] command = "cargo check"` (optional `timeout = 300`, `auto_send = false`) in `projects/<id>.toml`. After an ACP turn that changed files, Qur runs it in the task's worktree through the login shell; the output goes into the chat, the agent's button shows `checking…` then `✕ checks` on failure, and the failure is prefilled into the prompt (sent right away only with `auto_send`). Agent > Run Checks Now runs it by hand, also for Agent Terminals, where a failure is pasted into Claude's input line without Enter. A timeout kills the check's process group. No crates added; nothing runs unless the command is set.
    - **Run Project in Worktree** (Agent menu and palette). `[run] command = "pnpm dev --port $PORT"` and `url = "http://localhost:$PORT"` in `projects/<id>.toml`. Qur picks a free port per task (also exported as `PORT`), starts the command in the task's worktree as a "run · <task>" terminal under TERMINALS, waits up to 30 s for the port to answer, then opens the URL in that agent's Browser (ACP) or the system browser (Agent Terminal). Only localhost URLs are accepted, so Qur makes no outbound call. Running it again shows the live session; Discard and post-merge cleanup stop the server, and so does quitting.
30. **M5: terminal agents** (owner, 2026-10-23: "go for m5"; naming: "agent terminal names should be named by the main agent, or the user, related to what it's working on").
    - **Task text for terminal-mode agents:** `prompt` in `agents.toml`: `"arg"` (last argument, e.g. `claude "…"`), a flag such as `"--message"` (Aider), or `"type"` (default: typed in with Enter once the agent first goes quiet). Only on the first start, never on a restart. `[worktree] setup` now runs for them too, in their terminal, before the agent.
    - **Turns for Agent Terminals:** "busy, then quiet for 2 s, having changed files" counts as a turn. With `[checks] terminal = true` it runs the project's checks; off by default because a pause isn't always a finished turn.
    - **Names:** an agent's button shows, in order: the name you gave it (Agent > Rename Agent…, or double-click the button), else what the agent says it's working on (its terminal title, e.g. Claude Code's summary; generic titles are ignored), else the first line you typed, else "agent terminal n". An empty rename goes back to following the agent. Saved with the task.
    - **Terminal basics:** Find in Terminal (`Cmd+F`, regex, ↩ older / ⇧↩ newer, through the scrollback) and Cmd-click to open URLs (system browser) and `path:line:col` (code modal at that line, resolved from the session's folder).
31. **M6: search, alerts, first-run picker, Vim** (owner, 2026-10-23: "go for m6").
    - **Search** (`Cmd+Shift+F`, Replace `Cmd+Shift+H`, View > Search): a Search view in the stage, over the tree you're looking at (the selected agent's worktree, or the main checkout). Options Aa / ab / .* (⌥C ⌥W ⌥R). Replace All asks first. A one-line selection in the code modal seeds the query. `qur_search` uses `ignore` + `regex` (both already linked), not `grep-searcher`, so no crates are added.
    - **Alerts** (`[alerts] notify / badge / sound`, all on): a structured agent finishing a turn, erroring or needing approval, or an Agent Terminal going quiet after 7 s or more of output, alerts once when Qur isn't in front on that agent: a notification (GPUI's; needs the bundled app), the Dock badge (agents needing you, across windows) and an 18.5 KB chime. Clicking the notification shows the agent; selecting it clears the badge.
    - **First-run picker** (Qur > Setup…): agents found on PATH (Claude Code via ACP and as a terminal agent, Aider) with a Check (ACP `initialize`, or `--version`), the stage layout, keys (VS Code or + Vim), and the theme with live previews. Enter saves, Esc cancels. 32. **Rearrangeable stage** (owner, 2026-10-23: "add ability to restructure the terminal, viewing window and stuff, like photoshop or vscode"). Amends decisions 25 and 27. The agent stage is a dock (`dock.rs`): a tree of panes, each with tabs. Structured agents have Chat, Live, Browser, Changes and To-do; Agent Terminals have Terminal, Live and Changes.
    - Drag a tab onto a pane's edge to split it there, or onto its middle to join it. Drag a divider to resize.
    - Close a tab (×) to tuck it away; the pane's "+ Live" etc. bring it back. The agent's own Chat/Terminal can't be closed.
    - One arrangement for structured agents and one for Agent Terminals, shared by all agents and windows, saved as `[layout] acp` / `terminal` in config.toml as you change it.
    - The peek layouts A/B/C are now presets (View > Peek Layout, `Cmd+K Cmd+L`, the first-run picker), and resetting to one replaces both arrangements. An Agent Terminal's preset is still the terminal filling the stage (decision 27). `Cmd+1..5` brings that panel to the front wherever it's docked. When To-do isn't visible, Chat shows the plan.
33. **No logo in the top bar** (owner, 2026-10-23: "remove qur logo on top left"). Amends decision 1: the top bar now starts with the project switcher after the traffic lights. The brand marks stay in About and the first-run picker.
34. **M7: packaging** (owner: "m7"). `scripts/bundle.sh` builds Qur.app (`ph.peur.qur`), with the icon from the brand kit: the 3D render at 128 px and up, and the flat small symbol below 96 px, on Apple's rounded-tile grid. 35. **Layout visualizer, accent color** (owner, 2026-10-24: "i want a visualizer on agent stage layout"; "let user pick the accent color, dont feelin the default orange"). Qur > Accent Color… (also in the picker) picks which of the theme's six accents leads; agents take the palette in order from it. Hover previews, click saves `[ui] accent` (0 = the theme's first, Qur's orange). Swatches come from the theme, so they stay contrast-checked.
    - Amended 2026-10-25 (owner: "why always the yellow accent… follow the chosen theme or accent color of the user… make a brightness and color slider for the accents"): focus outlines, divider hovers, dragged tabs and links use your accent, not the theme's own `focus_ring`. Accent Color… adds a Color slider (turns every accent around the color wheel, −180°..180°, `[ui] accent_hue`) and a Brightness slider (lighter or darker, never white or black, `[ui] accent_brightness`), each track painted with the colors it gives; dragging previews and releasing saves. Tuned accents get their heat tints worked out again so file rows stay readable. Colors a terminal program draws itself (Claude Code's prompt, for one) come from the theme's terminal palette and don't change.
36. **Owner fixes from using the app** (2026-10-24):
    - **`claude: command not found` when opened from Finder:** the agents' PATH now comes from an *interactive* login shell (it reads `~/.zshrc`, where `~/.local/bin` and nvm are often added), and Qur's terminals get that PATH.
    - **The first Agent Terminal works in the project folder** ("i want it to default to /users/yobi/qur, thats how normal terminals work"), like a normal terminal: no worktree, `in_root` on the task. While one does, more get their own worktree so two agents never edit the same files. Merge doesn't apply (its edits are already in your folder); Delete becomes **Close Agent**, which stops it and deletes nothing. `qur_worktree::remove` refuses the project folder outright.

    - **Transparency:** translucent backgrounds were stacked (window + stage + panel), so 60% looked like ~85%.     - **Terminal replies:** Qur's terminals now answer programs' status and color queries (cursor reports, OSC 10/11 background), which were dropped. The Claude Code mascot's black bars on light themes come from Claude's own `theme = dark` setting (run `/theme` in Claude to switch).

37. **Terminal drawing and paste** (owner, 2026-10-24: "fix the image of claude code in qur… also let me paste images and files into qur terminal"). Block elements (`▀▄█▌▐▛▜▙▟▘▝▖▗`, eighths, shades) and box-drawing lines (`─│┌┐└┘├┤┬┴┼`, rounded and heavy forms) are drawn as rectangles that fill the cell, as Alacritty and Zed do, instead of with the font, whose glyphs don't fill Qur's taller lines. That gap was the "broken" Claude Code mascot (the black bars on light themes were the gaps, not Claude's theme). Paste, following Zed: an image on the clipboard sends Ctrl+V (Claude Code reads the clipboard image itself); files copied in Finder paste as shell-quoted paths; files dragged onto a terminal insert their paths.
38. **Transparency slider: 60% to 100% on every theme** (owner, 2026-10-24: "why isnt the transparency slider working… 60% to 100%"). Amends decision 8. Each theme had its own contrast-based floor that the slider couldn't go below (Solarized 100%, One Dark 92%, Catppuccin Latte 87%), so on many themes it barely moved or didn't move at all. Now `MIN_OPACITY = 0.6` is the only limit. `Theme::min_opacity` still reports each theme's readable-over-any-desktop floor in the contrast test, for information; on themes above 60%, text over a very bright or dark desktop can dip below 4.5:1 at the low end, which blur (on by default) softens.
39. **Split terminals** (owner, 2026-10-24: "make split terminals a thing like in linux"). A shell or Agent Terminal splits like iTerm or Terminator: Terminal > Split Right `Cmd+D`, Split Down `Cmd+Shift+D` (terminal focused; `Cmd+D` stays Add Next Match in the editor).
    - The new pane is a shell in the project folder, like `Cmd+T` (which now always opens there too, not in the selected agent's worktree; Open Task Worktree in Terminal is the way into a worktree).
    - Panes belong to the sidebar row they were split from and get no row of their own. Selecting the row focuses the pane you were last in. The focused pane has an accent line on top; `Cmd+Opt+Arrows` or a click moves focus; dividers drag to resize.
    - `Cmd+W` closes the focused pane and its neighbour takes the space. Closing a shell row's first pane hands the row to the pane beside it; when an Agent Terminal or Run Project terminal ends, its split shells close with it.
    - Splits aren't saved across restarts (terminals aren't either).
    - Tiling like a Linux window manager (owner: "when i do a shortcut the terminal splits like in archlinux… a bunch of terminals in one window view like in orca"): `Cmd+Enter` (i3's Mod+Enter) adds a shell and splits the focused pane along its longer side (dwindle), so the panes keep filling the view. `Cmd+D` / `Cmd+Shift+D` still pick the direction.
    - Amended 2026-10-25 (owner: "split terminals … should be relatively square", then "make cmd+d dwindle"): `Cmd+Enter` lays the row's panes out as a grid, choosing the row count that keeps each pane closest to square (wide panel: 2 side by side, 4 as 2×2, 5 as 3 over 2), and closing a pane lays the grid out again. `Cmd+D` (Split (Dwindle)) halves the focused pane along its longer side, and `Cmd+Shift+D` splits it below; either one leaves the row's layout alone from then on. Panes are rounded tiles with gaps, and the focused one is outlined in the accent (Hyprland's look).
    - Amended 2026-10-26 (owner: "the latest or smallest terminal is the first to be cmd + w'd"): in a dwindled row `Cmd+W` closes the newest pane (the smallest) whichever pane is focused, and focus stays put. A grid row still closes the focused pane.
